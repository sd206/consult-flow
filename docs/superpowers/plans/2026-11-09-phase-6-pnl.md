# Phase 6: P&L Reporting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admins and Managers see an accurate profit and loss report for any date range. It can be grouped by month, quarter, client or project, filtered by clients and projects, and exported to CSV.

**Architecture:**
- **SQL functions:** all aggregation happens in two `stable security definer` SQL functions.
  - `pnl_facts` returns one row per financial fact, with its date, client, project, measure and exact amount.
  - `pnl_report` filters and groups those facts and returns finished rows: one per group, plus an overhead row and a totals row, with every figure as a string.
- **TypeScript:** reads the rows, formats them, and builds the CSV with a pure, unit-tested function.
- **The page** is a server-rendered filter form plus a table. The CSV comes from a route handler that uses the same data function.

**Tech Stack:** Same as Phases 1–5. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-08-consulting-ops-design.md`. Relevant sections: 3.2 (reports row), 5.5 (including Phase 6 decisions 1–6), 7, and 9 (phase 6).

## Global Constraints

- **Carried over:** everything in the Phase 1–5 Global Constraints still holds. Money is `numeric`, summed in SQL and moved as strings. Errors go only through `mapDbError`. Every new SQL function uses `set search_path = ''`, fully qualified names, revoke from public/anon and an explicit grant.
- **Measures** (each by its own date, all in the firm's single currency):
  - `revenue_hours` = hours × `client_rate_snapshot` for entries on **approved** timesheets, by `work_date`. The client comes from the project.
  - `labour` = hours × `cost_rate_snapshot` for the same entries.
  - `revenue_fees` = `amount` of `manual` invoice lines on invoices with status `issued`, `partly_paid` or `paid`, by `issue_date`. These have a client and no project.
  - `discount` = `discount_amount` of those invoices, by `issue_date`. Client only.
  - `invoiced` = `subtotal − discount_amount` of those invoices, by `issue_date`. Client only.
  - `collected` = for each payment on a non-void invoice with `total > 0`, `round(amount × (total − tax_amount) / total, 2)`, by `paid_on`. Client only.
  - `direct_expense` = `amount` of expenses with a client or a project, by `spent_on`. Uses the expense's client and project.
  - `overhead` = `amount` of expenses with neither, by `spent_on`.
- **Derived per row:**
  - `revenue = revenue_hours + revenue_fees − discount`
  - `gross = revenue − labour`
  - `net = gross − direct_expenses − overhead`. Overhead is non-zero only in month/quarter rows, the overhead row and totals.
  - `margin = round(net / revenue × 100, 1)`, or null when revenue = 0.
- **Rounding:** sum the exact products for the group, then round to 2 dp once per measure, per row. Totals are computed from the facts, not by adding rounded rows. Collected is the exception: it is rounded per payment.
- **Grouping:**
  - `month` gives one row per calendar month in `[from, to]`, including empty months. Label `Jan 2026`, sort key `2026-01`.
  - `quarter` gives one row per quarter in range. Label `2026 Q1`.
  - `client` gives one row per client with any fact in range. Label is the client name, sorted by name.
  - `project` gives one row per project with any fact, labelled `{client} — {project}`. Facts with a client but no project go to a row `{client} — no project`. Sorted by client, then project, with the no-project row last for each client.
  - Month/quarter rows include overhead. Client/project rows don't; overhead appears in a separate `Unallocated overhead` row. Every grouping ends with a `Total` row.
  - A month/quarter row's facts include everything dated in that period, with or without a client.
- **Filters:**
  - `from`/`to` are inclusive dates. `to ≥ from`, at most 3 years apart (`'Choose a range of 3 years or less.'`).
  - `clients` (uuid[], null = all) and `projects` (uuid[], null = all) keep facts whose client or project is in the list. A project filter excludes facts that have no project.
  - With any client or project filter, overhead is 0 everywhere and the overhead row is omitted.
- **Roles:** Admins and Managers only. Consultants get 404 / `42501`.
- **CSV:**
  - UTF-8 with BOM, CRLF line endings, comma separator.
  - Fields containing a comma, quote, CR or LF are double-quoted, with quotes doubled.
  - Columns: `Group, Revenue from hours, Fees, Discounts, Revenue, Labour cost, Gross profit, Direct expenses, Overhead, Net profit, Margin %, Invoiced, Collected`.
  - Amounts are plain decimals (`1234.50`, `-12.00`). Margin is `12.5`, or empty.
  - Text cells starting with `=`, `+`, `-`, `@`, tab or CR are prefixed with `'`.
  - Filename: `pnl-{from}-to-{to}-by-{group}.csv`.
- **Migration file:** `20261109000025_pnl.sql`. Then run `npm run db:reset && npm run db:types`.
- **E2E:** runs against a production build with `workers: 1`; each test creates its own firm.

## Review Focus

1. **Worked in March, invoiced in April, paid in May.** The revenue and labour fall in March. Invoiced falls in April. Collected falls in May, net of tax. Test in Task 1.
2. **Hours that shouldn't count:** draft, submitted and rejected timesheets contribute nothing. A timesheet reopened after approval drops out until it is re-approved. Test in Task 1.
3. **A voided invoice:** its fees, discount and invoiced amount disappear, but the approved hours behind it still count as revenue. Test in Task 1.
4. **Partly paid invoice with 8.25% tax:** collected excludes tax exactly, to the cent. Payments summed per row match the hand calculation. Test in Task 1.
5. **A client named `=HYPERLINK("x")`:** it is exported as a harmless text cell. Negative amounts are still plain numbers. Test in Task 2.

**Interfaces:**
- **`pnl_facts`.** Signature:
  `public.pnl_facts(p_firm uuid, p_from date, p_to date) returns table (fact_date date, client_id uuid, project_id uuid, measure text, amount numeric)`.
  - Stable and security definer. Raises `42501` unless `has_role(p_firm,'{admin,manager}')`.
  - `measure` is one of `revenue_hours`, `labour`, `revenue_fees`, `discount`, `invoiced`, `collected`, `direct_expense`, `overhead`.
  - Amounts are exact numerics (no rounding), except `collected`, which is rounded per payment.
  - Only facts with `fact_date` between `p_from` and `p_to` are returned.
  - Every join is scoped by `firm_id`.
- **`pnl_report`.** Signature:
  `public.pnl_report(p_firm uuid, p_from date, p_to date, p_group text, p_clients uuid[], p_projects uuid[]) returns table (row_kind text, group_key text, label text, sort_key text, revenue_hours text, fees text, discounts text, revenue text, labour text, gross text, direct_expenses text, overhead text, net text, margin text, invoiced text, collected text)`.
  - Stable and security definer. Raises `42501` unless admin/manager.
  - `p_group` must be one of `month`, `quarter`, `client`, `project`. Otherwise it raises `PNL_GROUP_INVALID`.
  - Raises `PNL_RANGE_INVALID` when `p_to < p_from` or the range exceeds 3 years.
  - `row_kind` is `group`, `overhead` or `total`.
  - All money is returned as `numeric(14,2)::text`. `margin` is `numeric(7,1)::text` or null.
  - Rows are ordered: groups by `sort_key`, then overhead, then total.
  - `group_key` is the period start date (`YYYY-MM-01` for month and quarter), the client id, the project id, or `client:{id}` for no-project rows.
  - Implements the grouping, filtering and rounding rules in Global Constraints.

**Interfaces:**
- **Types.**
  - `PnlGroup = 'month' | 'quarter' | 'client' | 'project'`
  - `PnlParams = { from: string; to: string; group: PnlGroup; clientIds: string[] | null; projectIds: string[] | null }`
  - `PnlRow = { kind: 'group' | 'overhead' | 'total'; key: string; label: string; revenueHours: string; fees: string; discounts: string; revenue: string; labour: string; gross: string; directExpenses: string; overhead: string; net: string; margin: string | null; invoiced: string; collected: string }`
- **`parsePnlParams(search: Record<string, string | string[] | undefined>, today: string): Result<PnlParams>`** (pure).
  - Defaults: `from` = Jan 1 of `today`'s year, `to` = `today`, `group` = `month`.
  - `client`/`project` may be repeated; non-uuids are dropped, and an empty list becomes null.
  - Invalid dates, a reversed range or more than 3 years fail with the `PNL_RANGE_INVALID` message text. An unknown group fails with the group message.
- **`getPnl(db, firmId, params): Promise<Result<PnlRow[]>>`** calls `rpc('pnl_report')` and maps errors with `mapDbError`.
- **`buildPnlCsv(rows: PnlRow[], params: PnlParams): { filename: string; body: string }`** (pure). Implements the CSV rules in Global Constraints. The label cell for an overhead row is `Unallocated overhead`, and for the totals row is `Total`.

    - The overhead row is labelled `Unallocated overhead`. The total row is bold, labelled `Total`.
